## 1. Что увижу на экране

### Строка в таблице «Сюжет»

Как сейчас: № | говорящий | **Русский (в игре)** | English | Chinese. Под русским текстом — список
вариантов, по порядку:

1. **Утверждённый** (если есть) — пометка «утверждено», кто и когда утвердил.
2. **Как в игре** — нынешний текст из словарей ArknightsRU.
3. **Предложения переводчиков** — по числу «согласен», больше — выше. У каждого: автор, дата,
   «изменено», если правили.
4. **Сова**, 5. **ИИ** — как сейчас, своим тоном.

У каждого варианта справа маленькая кнопка **«Согласен»** со счётчиком (наведение / нажатие — список,
кто согласен). Повторное нажатие снимает своё «согласен». У редактора у каждого варианта ещё кнопка
**«Утвердить»** (у утверждённого — «Снять утверждение»).

Под вариантами — строка действий (видна при наведении на строку и с клавиатуры):

- **«Взять вариант Совы» / «Взять вариант ИИ»** — создаёт моё предложение с этим текстом (сразу
  открывается для правки — можно поправить падеж и сохранить);
- **«Написать свой»** — поле ввода прямо в строке, заполнено текстом «как в игре»; «Сохранить» /
  «Отмена»; Ctrl+Enter — сохранить. При ошибке — предупреждение: сломан тег (`<color…>` без пары),
  пропал `{0}`/`{@nickname}`, есть `\n` в другом количестве, чем в английском. Нет ошибки — ничего не
  показываем;
- **«Оставить как в игре»** — голос «текущий перевод хорош» (это то же «согласен» у варианта «как в
  игре»);
- **«Комментарий»** — короткая заметка к строке (замечание, вопрос). Комментарии — под вариантами,
  серым тоном (место и тон уже заложены в коде: `VARIANT_TONE.comment`), с автором и датой; автор и
  редактор могут отметить «решено» — тогда комментарий сворачивается.

Строки, где есть предложения или комментарии, помечены точкой в колонке №; фильтр над таблицей:
«все / с предложениями / с комментариями / утверждённые».

Если тот же английский текст встречается в других историях — у поля правки пометка «эта строка есть
ещё в N местах — правка подействует везде» со списком мест (см. §2, почему).

### Вкладка «Мои правки»

Таблица моих предложений: **было** (как в игре) / **стало** (моё) / **где** («Сюжет › Глава ›
история › № строки», ссылка на строку) / статус («предложено», «согласны: 3», «утверждено»,
«устарело» — английский в игре изменился) / дата. Действия: «Переписать» (то же поле правки),
«Удалить», «История» (все прежние версии текста с датами).

Переключатель «Мои / все» (все — для редактора: что ждёт утверждения).

Кнопка **«Выгрузить для XUnity»** — скачивает файл словаря (см. §3).

## 2. Как хранится

Новые таблицы в схеме `translators` (своя миграция `t003_edits.sql`, чужие таблицы не трогаем).

**Ключ строки — английский текст.** Словари XUnity сопоставляют по английскому тексту, а не по месту
в сюжете: один и тот же английский в разных историях — это одна запись словаря и один перевод в игре.
Поэтому предложение и утверждение привязаны к английскому тексту; место (история, строка), где
правку сделали, хранится для показа и ссылки.

| таблица | что в ней |
|---|---|
| `members` (есть) + колонка `role` | `translator` (по умолчанию) / `editor` / `admin` |
| `proposals` | id, `en` (ключ), `text`, `source` (`own` / `sova` / `ai`), автор, создано, изменено, удалено (мягкое удаление), место: `story_id`, `line`, `part` |
| `proposal_versions` | каждая прежняя версия текста: proposal_id, текст, кто, когда — это и есть «История» |
| `agreements` | proposal_id (или «как в игре» для `en`), user_id, когда; один голос на человека и вариант |
| `approvals` | `en` → утверждённый вариант (proposal_id или «как в игре»), кто, когда; одна запись на `en`, история утверждений — в `approval_log` |
| `comments` | id, `en`, место, автор, текст, создано, «решено» (кто, когда) |

После каждого импорта: если английского текста предложения больше нет в сюжете — предложение
помечается «устарело» (не удаляется). Перевод «как в игре» берётся из импорта, не копируется.

## 3. Выгрузка в формат словарей XUnity

- В файл идут **только утверждённые** варианты, отличающиеся от «как в игре» (утверждённое «как в
  игре» — ничего не меняет, строку не пишем).
- Кодирование — ровно как в ките (`/mnt/f/arkrutrinstr/CLAUDE.md` §3.2): `\` → `\\`, `=` → `\=`,
  перевод строки → `\n`, второй `/` в `//` → `/`, `%3D` и директивы `#set…` экранируются; ключ,
  начинающийся с `r:`/`sr:`, и пустое значение выгрузить нельзя — такие строки в отчёте выгрузки.
  Проверка-тест: разбор (§3.1) выгруженной строки возвращает ровно (ключ, значение).
- Ключ — английский текст **как в исходном словаре** (тот, что нашёл импорт), не как в сценарии.
- Файл UTF-8 без BOM, LF. Имя — `00_translators.txt`: по порядку загрузки (§3.3) файлы `00_…`
  грузятся позже `11_…`/`12_…` и перекрывают их.
- В начале файла — комментарии `//`: дата выгрузки, число строк, кто выгрузил.
- Строки, которые показывает плагин RichTextFix (пометка «строка из плагина»), выгружаются, но в
  отчёте выгрузки — предупреждение «правка через словарь может не подействовать».

## 4. Роли

| роль | может |
|---|---|
| участник (`translator`) | читать раздел, предлагать, «согласен», комментировать, править и удалять **свои** предложения и комментарии, выгружать файл |
| редактор (`editor`) | всё то же + «утвердить» / «снять утверждение», отмечать любые комментарии «решено», видеть «все правки» |
| админ (`admin`) | всё то же + добавлять участников и менять роли (сначала командой/SQL, страница — потом) |

## 5. Сколько работы

Оценка в рабочих сессиях (как эта ночь):

| часть | объём |
|---|---|
| таблицы, API (предложить, переписать, удалить, согласен, утвердить, комментарии), права по ролям, тесты | 1–1,5 |
| строка «Сюжета»: варианты по порядку, «согласен», действия, поле правки с проверкой тегов | 1–1,5 |
| «Мои правки» + история версий | 1 |
| выгрузка XUnity (кодировщик, тест «туда-обратно», отчёт выгрузки) | 0,5 |
| «устарело» после импорта, ручная проверка, правки по замечаниям | 0,5–1 |
| **итого** | **≈ 4–5 сессий** |

Порядок: сначала таблицы + API + «Написать свой» + «Мои правки» (можно пользоваться без
утверждения), затем «согласен», затем утверждение и выгрузка.
