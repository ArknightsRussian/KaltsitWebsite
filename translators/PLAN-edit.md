# План: правка строк во вкладке «Сюжет»

Статус: **план принят заказчиком 2026-11-09 с поправками** (они внесены ниже). Делается по частям, следующая —
только после «да» заказчика:

1. таблицы (миграция `t003`) + статусы + API + «Написать свой» / «Взять вариант» / «Оставить как в игре» +
   комментарии + «Мои правки» с историей версий + осторожность при правке (§5);
2. автоматические отметки у вариантов и «рекомендуем» (§3);
3. «согласен», «сцену прочитал», прогресс (§4);
4. утверждение (по строке и пачкой) и выгрузка (§6).

## 1. Ключ правки и статус строки

- **Ключ — английский текст записи словаря.** Словари XUnity сопоставляют по английскому тексту, а не по месту в
  сюжете: один и тот же английский в разных историях — одна запись словаря и один перевод в игре. Поэтому
  предложения, «согласен», утверждение и комментарии привязаны к ключу, одно решение действует во всех местах.
  Место (история, строка, часть), где правку сделали, хранится для показа и ссылки.
- Какой текст ключ: запись словаря, которую нашёл импорт (`story_lines.edit_key`); если запись не нашлась целиком
  (реплика собрана по частям, строка только у плагина или перевода нет) — весь английский текст реплики в виде,
  как его видит плагин (без тегов, `\n` — перевод строки).
- **Статус строки** (по ключу), правило — в одном месте кода (`translators/edits/status.rs`):
  - «не проверено» — по умолчанию;
  - «есть предложения» — есть хоть одно живое предложение;
  - «утверждено» — ведущий утвердил вариант; в т.ч. «как в игре — проверено» (в выгрузку не идёт);
  - «устарело» — утверждение или предложение относится к английскому тексту, которого после импорта на этом месте
    (или вообще в сюжете) больше нет. Ставится импортом, не удаляется: видно в «Мои правки» и у строки на прежнем
    месте («было для английского: …»).

## 2. Что увижу на экране

### Строка таблицы «Сюжет»

Как сейчас: № | говорящий | **Русский (в игре)** | English | Chinese. У № — точка-статус (тон из проекта).
Под русским — варианты по порядку:

1. **Утверждённый** (если есть) — «утверждено», кто и когда;
2. **Как в игре** — текст из словарей ArknightsRU (сама верхняя строка ячейки);
3. **Предложения переводчиков** — по числу «согласен», больше — выше; автор, дата, «изменено»;
4. **Сова**, 5. **ИИ** — как сейчас, своим тоном.

Действия — в меню у номера строки (кнопка-карандаш в колонке №; ряд кнопок под каждой репликой делал таблицу
вдвое выше):

- **«Взять вариант Совы» / «Взять вариант ИИ»** — открывает поле правки, заполненное этим текстом; «Сохранить» —
  и это моё предложение (источник `sova` / `ai`);
- **«Написать свой»** — поле правки прямо в строке (`Textarea`), заполнено «как в игре» (или моим предложением,
  если оно уже есть); «Сохранить» / «Отмена»; Ctrl+Enter — сохранить, Esc — отмена;
- **«Оставить как в игре»** — то же, что «согласен» у варианта «как в игре»; повторное нажатие снимает;
- **«Комментарий»** — короткая заметка (автор, дата); автор или ведущий отмечает «решено» — комментарий
  сворачивается в строку «решённых: N».

У моего предложения — «Изменить», «Удалить». Предложение у человека на ключ одно: «Написать свой» / «Взять
вариант» при уже имеющемся — новая версия моего предложения (старая — в истории).

### Вкладка «Мои правки»

Таблица: **было** (как в игре) / **стало** (моё) / **где** («Сюжет › Глава › история › № строки», ссылка на
строку) / статус / дата. Действия: «Переписать» (то же поле правки), «Удалить», «История» (все версии текста с
датами). Переключатель «Мои / все» — только ведущему. Кнопки выгрузки — §6 (часть 4).

## 3. Автоматические отметки у каждого варианта (часть 2)

У «как в игре», каждого предложения, Совы и ИИ:

- **глоссарий** ✓ / ✗ — как сейчас у русского, но по тексту этого варианта;
- **теги и подстановки** — `<…>` парные, `{0}` / `{@nickname}` и т.п. те же, что в английском, число `\n` как в
  английском; **показываем только при ошибке**;
- **длина** — «заметно длиннее, чем в игре», если длиннее «как в игре» больше чем на 30 % **и** больше чем на
  15 знаков (короткие реплики не дёргаем); порог — одна константа;
- **ты / вы** — по словам-признакам (ты, тебя, тебе, твой… / вы, вас, вам, ваш…, без учёта регистра, ё=е):
  совпадает ли обращение с соседними репликами того же говорящего в этой сцене (берём большинство по сцене);
  нет признаков — отметки нет;
- **число «согласен»**.

**«Рекомендуем»** — на одном варианте: из прошедших все проверки — предложение с наибольшим «согласен», иначе
Сова, иначе ИИ, иначе как в игре. Правило — одна функция в одном месте кода, легко поменять.

## 4. «Согласен», «сцену прочитал», прогресс (часть 3)

- «Согласен» у каждого варианта со счётчиком (наведение — кто); повторное нажатие снимает. Для ведущего — подсказка.
- Кнопка **«Сцену прочитал»** у истории: кто и когда (список виден над таблицей).
- **Прогресс** у главы и истории: % проверено (утверждено), ждут решения (есть предложения), устарело — в списке
  глав (выбор главы и истории) и над таблицей (компонент `Progress`/`Meter` проекта).

## 5. Осторожность при правке (часть 1)

- Английский текст встречается **больше чем в 20 местах** — перед сохранением отдельное подтверждение
  (`AlertDialog`) со списком мест; **2–20 мест** — пометка у поля «эта строка есть ещё в N местах — правка
  подействует везде» со списком мест по нажатию.
- Строки только из знаков препинания / многоточий (нет ни буквы, ни цифры) — правку не даём (кнопок нет, API
  отвечает 400).
- **Многострочные реплики**: правка части сохраняется как правка всей записи словаря (ключ — весь английский
  текст записи); в поле правки видны все части (переводы строк сохраняются).
- В `proposals.source` есть значение `kit` (на будущее — отчёты редактор-кита), сейчас не используется.

## 6. Ведущий и выгрузка (часть 4)

- **Ведущий — один человек** (роль `editor`; без нескольких редакторов и споров между ними): утвердить вариант
  у строки; пачкой по истории — «утвердить рекомендованное во всей сцене, кроме отмеченных» и «вся сцена — как в
  игре, проверено»; фильтр над таблицей «есть предложения / рекомендации / устарело / с комментариями».
  Роль выдаётся командой (`translators/role.sh`); локально — `dev-translator`, чтобы заказчик проверил сам.
- **Два режима выгрузки:**
  - «утверждённое» — для игры: только утверждённые варианты, отличающиеся от «как в игре»;
  - «все предложения — на проверку» — неутверждённые; в имени файла и в шапке явно `REVIEW` / «не для игры без
    проверки»; доступен всем участникам.
- **Два формата** (с Kolooo ещё не согласован — поддерживаем оба):
  - (а) отдельный файл `00_translators.txt` (`00_translators_REVIEW.txt`); в отчёте выгрузки — какие файлы его
    перекрывают по порядку загрузки (§3.3 кита: по полному пути по убыванию, позже загруженный побеждает),
    например `00_arktr_story.txt`, `00_review_*.txt`;
  - (б) «заплатка»: копии `11_ui.txt` / `12_story.txt` / `13_names.txt` с заменёнными значениями у затронутых
    ключей (исходные файлы не трогаем), архивом.
- **Кодирование** — ровно как в ките (`/mnt/f/arkrutrinstr/CLAUDE.md` §3.2): `\` → `\\`, `=` → `\=`, перевод
  строки → `\n`, `//` и `%3D` и директивы `#set…` экранируются; ключ `r:`/`sr:` и пустое значение выгрузить
  нельзя — такие строки в отчёте. Тест «туда-обратно»: разбор (§3.1) выгруженной строки возвращает ровно
  (ключ, значение). UTF-8 без BOM, LF; шапка `//` с датой, числом строк, кто выгрузил.
- Строки из плагина RichTextFix — **отдельным CSV «для плагина»** (ключ, роль плагина, было, стало), в словарный
  файл не кладём.

## 7. Как хранится

Новые таблицы в схеме `translators` (миграция `t003_edits.sql`; чужие таблицы не трогаем):

| таблица | что в ней |
|---|---|
| `members` + колонка `role` | `translator` (по умолчанию) / `editor` / `admin` |
| `story_lines` + колонка `edit_key` | ключ правки (§1), заполняет импорт |
| `proposals` | id, `edit_key`, `text`, `source` (`own` / `sova` / `ai` / `kit`), автор, создано, изменено, удалено (мягко), место (`story_id`, `line`, `part`), `outdated_at` |
| `proposal_versions` | каждая версия текста: proposal_id, текст, источник, кто, когда — это «История» |
| `agreements` | `edit_key` + proposal_id (пусто = «как в игре»), user_id, когда; один голос на человека и вариант |
| `approvals` | `edit_key` → утверждённый вариант (proposal_id или «как в игре»), текст на момент утверждения, кто, когда, `outdated_at`; история — `approval_log` |
| `comments` | id, `edit_key`, место, автор, текст, создано, удалено, «решено» (кто, когда), `outdated_at` |

Часть 3 добавит `story_reads` (история, кто, когда) своей миграцией `t004`.

После каждого импорта: если ключа больше нет в сюжете — `outdated_at` ставится (запись не удаляется); ключ
вернулся — снимается. Перевод «как в игре» берётся из импорта, не копируется.

## 8. Роли

| роль | может |
|---|---|
| участник (`translator`) | читать раздел, предлагать, «согласен», комментировать, править и удалять **свои** предложения и комментарии, отмечать «решено» у своих комментариев, выгрузка «на проверку» |
| ведущий (`editor`) | всё то же + утверждать, отмечать «решено» у любых комментариев, «все правки», выгрузка «утверждённое» |
| админ (`admin`) | всё то же + роли (пока командой) |

## 9. Что не делаем сейчас

Совместное редактирование в реальном времени, уведомления, отчёты кита (только место под `kit`), правку вне
«Сюжета» (интерфейс, имена) — это вкладка «Термин» и позже.
